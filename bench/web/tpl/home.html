把引擎差距，摆到桌面上比

网站简介

这是面向引擎开发与客户端技术决策者的源码级比较项目。比较对象固定为 Cocos Creator 3.8.8、LayaAir 3.4.0 与内部维护的 Egret 5.4.1 分支；重点不是 API 罗列或主观体验， 而是沿着实际渲染与发布链路定位可复核差异：渲染数据如何收集、何时断批、命令怎样提交、 WebGL/WebGPU 后端在哪一层分叉，以及这些实现细节如何反映到帧时间与 draw call。

证据按强度分层：引擎源码用于确定机制与调用路径；官方文档用于确认公开契约和平台能力； 统一基准用于量化特定版本、设备和场景下的结果。源码结论标注具体引擎版本与文件路径； 实测数据保留 JSON、环境元数据与采样口径。不能由公开资料或单次测试推出的结论，不写成普适事实。

性能实验不是独立的 FPS 展示页：三家适配器共用同一份 sim-core（运动仿真、预热、采样和报告流程）， 使用 performance.now() 作为统一时间源，报告 p50/p95/p99 帧时间和 draw call。页面同时保留 2D 合批、WebGPU、编辑器/平台和生态等非跑分维度，服务于 2D/2.5D 重度 H5 MMO 的技术选型。

可审计材料（仓库根目录）： 《引擎选型对比报告》 · 《三引擎2D渲染管线对比》 · 《三引擎2D渲染管线源码级对比》 · 《WebGPU-2D渲染现状调研》 · 《自研引擎魔改思路总结》 · 《选型汇报稿》

架构与基本盘

Cocos Creator 3.8.8

雅基软件MIT（引擎）TS + C++/WASM

GFX 抽象层一套渲染代码对接 WebGL / WebGL2 / WebGPU / Vulkan / Metal / GLES 六种图形 API； 类 Unity 组件模型；Custom Pipeline 可编程管线；与微信、抖音平台官方深度共建，平台新能力通常首发适配。

LayaAir 3.4

LayaboxMIT（引擎）纯 TypeScript

全 TS 引擎读源码、改引擎门槛最低（AS3/Egret 页游团队迁移友好）；2D Sprite 与 3D Sprite3D 双树分离，混排心智负担略高；WebGPU 投入激进，3D 管线对 WebGPU 优化较深。

自研 Egret 5.4.1

内部维护WebGL 基线魔改WebGPU 后端自研

原生 Egret 基础上叠加：动态合图（2048 大图集×10，跨图片合批）、 SDF 文字渲染（设计时对标 Godot 的 MSDF 文字方案）、etc_alpha_mask 双纹理、 以及多纹理合批的 WebGPU 后端（一个 bind group 挂多张图集）。

维度判断工程含义与判断边界
2D/2.5D 渲染成熟度Cocos为何：2D 的 Batcher2D、UITransform、Mask/裁剪、材质与渲染数据组装在同一套 UI 管线中长期迭代；对大量 Sprite、UI、文字混排的常规项目，默认路径更完整。
不代表：不表示每个 2D 场景都更快；资源是否同图集、节点顺序、字体和遮罩仍决定最终 draw call。
重度 3D 渲染上限LayaAir为何：Laya 近年把 WebGPU、PBR、ClusterLighting 和 3D 发布链路作为重点投入，纯 3D 场景可直接利用这些路径。
不代表：WebGPU 并非所有平台可用；实际项目仍须按目标浏览器、模型/材质复杂度和 GPU 重跑 3D 基准。
微信 / 抖音小游戏适配Cocos为何：官方发布面板、平台适配和包体裁剪工作流更成熟，遇到平台 API 或构建问题时可查资料和案例更多。
不代表：Laya 不能发布两平台；这是交付风险、工具链与排障成本的比较，不是运行时性能结论。
编辑器 / 工具链Cocos为何：场景、Prefab、动画、UI、构建、调试等工作流集成度较高，编辑器扩展与现成团队经验更多。
代价：抽象层多、工程结构更重；需要改底层或定位极端性能问题时，链路未必比纯 TS 短。
文档与社区 / 招聘Cocos为何：中文教程、第三方插件、问题检索结果和具备 Creator 经验的人才池通常更多，降低新人入场与线上问题排查成本。
边界：没有微信官方的精确引擎份额统计；这里是工程可获得性判断，不应解读为严格市场份额。
API 简洁度 / 上手LayaAir为何：显示对象、资源和事件 API 较直接，纯 TS 项目可较少经过组件/序列化层；AS3/Egret 或页游背景团队迁移路径更短。
代价：简单 API 不自动解决资源分组、图集、渲染顺序和性能规范，团队仍需建立自己的工程约束。
源码可读可改性LayaAir为何：主要运行时为 TypeScript，可在浏览器断点直接跟入；定制 2D/3D 行为的编译、调试和二次发布闭环较短。
边界：可读不等于改动风险低；渲染状态、资源生命周期和跨端兼容仍需要回归矩阵。
热更新灵活度平手Web：资源和脚本可由业务 CDN / 版本清单控制。
小游戏：分包、远程资源、代码包和审核策略由宿主平台约束；两家引擎都不能绕过平台规则，差别主要在各自发布工具的配置体验。
引擎迭代活跃度Cocos为何：COCOS 4 已发布且改为完全开源，Creator 3.8.x 仍有维护线，版本路线公开度较高。
迁移提醒：4.x 与当前 3.8 基线不是无成本替换；现有项目应把升级视为独立验证项目，而非自动性能收益。

阅读方式："判断"服务于当前目标（2D/2.5D 重度 H5 MMO，Web + 微信 + 抖音）；每行的"为何"是可讨论的工程依据，"不代表 / 代价 / 边界"限定其适用范围。出处：《引擎选型对比-Cocos-vs-LayaAir.md》§1/§2/§3（2026-07）。开发者规模、市占率为各厂商与第三方口径（微信官方未发布精确引擎占比）；Cocos 于 2025-11 被忽然科技收购，COCOS 4 已移除商业限制条款。

2D 渲染与合批机制

合批是 2D 性能的命门：同一屏精灵数下，drawCall 差 1000 倍就是流畅与卡顿的差距。三家思路完全不同。

引擎2D 合批思路多纹理交叉场景实测 dc（V4 · 10000 精灵）
Cocos 统一 Batcher2D 状态机：同材质+同 BlendState+同纹理源+同 Layer 连续才合批；WEBGL_multi_draw 扩展一次提交多图元 跨纹理不断批（multi_draw + 可选动态合图）≈10
LayaAir 普通 Sprite 可按同纹理 / 同图集合批；当前基准的交叉散图路径未启用自动动态合图，因而逐精灵提交。序列帧 / Graphics 走专用批处理 当前基准：未跨纹理合批——V4 的 12 张散图交叉排列，实测每精灵独立渲染元素；引擎另有 DynamicAtlasManager / 自动动态图集路径= 10000（=精灵数）
Egret 自研 WebGL：动态合图（TextureAtlasManager，≤512×512 纹理自动入驻 2048 大图集）；WebGPU：纹理槽合批（16 槽 bind group） 跨纹理合批（图集打包 / 多纹理槽）≈1~4

Laya 掉到一半帧率的三条源码级根因

  • 合批：在本站 V2/V4 的交叉散图标准 Sprite 路径中，未启用动态合图，dc 直接等于精灵数；这不等同于 Laya 2D 在同纹理/同图集路径完全不合批
  • 变换：Matrix.setMatrix 每帧每精灵无条件重算 6 次三角函数（skew=0 也算）→ 1 万精灵每帧 6 万次三角函数
  • WebGPU 提交：每帧对每个精灵跑一遍 _prepare 状态机（矩阵检查 + shader 比较 + 几何状态），开销随精灵数线性增长——这是它 WebGPU 反而更慢的原因

出处：《三引擎2D渲染管线对比.md》（2026-08-28 源码实查）+ 本站基准实测（见下文性能实测）。

WebGPU 现状（2D）

Cocos

同源管线，最干净：2D 渲染器与 WebGL 共用 Batcher2D + GFX 抽象，切后端只换 renderMode， dc 基本一致（V1-V4 均 ≈10）。WebGPU 后端标记实验性（Web-Desktop），实测可跑。

LayaAir

路径分叉，开销更大：WebGPU 2D 走逐元素 _prepare 状态机， 变换密集/多纹理场景 WebGPU 反而比自家 WebGL 慢（V3：WebGPU 41.4 vs WebGL 43.3 fps）。3D 侧 WebGPU 优化较深。

Egret 自研

后端级替换：实现 RenderBuffer/RenderContext 接口层，业务零改动； 多纹理合批（一个 bind group 挂多张图集），Bunnymark 承载力约为 WebGL 4-6 倍、dc 约 1/3000。

WebGPU 不是处处赢：GPU 填充率瓶颈时与 WebGL 同为 60fps，低端设备与部分浏览器上还可能更慢——负向结论同样如实记录。

方法论要点

  • 三引擎共用 sim-core（逐字节同一份）：物理推进、统计采样、流程驱动完全一致
  • 唯一时间源 performance.now()；tick 固定在帧回调最前端；>200ms 帧丢弃（后台切换 / 大 GC）
  • 动态预热：帧时滑动窗口收敛后才开始采样（防 WebGPU 首跑 PSO 编译污染）
  • 帧时间优先：p50 / p95 / p99 + 掉帧率；承载力走阶梯加压（持续掉帧即停）+ 临界点细扫 + 抖动重试
  • drawCall 口径逐引擎核对：hook 探针 + 引擎计数器双路径，含 WEBGL_multi_draw 扩展拦截；假渲染防护（截图 + probe 计数）
  • 公平性清单：同机、同浏览器版本、插电、独显、关无关插件；GPU 信息与画布尺寸随 JSON 归档
