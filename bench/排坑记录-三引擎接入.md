# 排坑记录 · 三引擎基准接入（2026-08-27）

> 背景：三引擎统一基准（sim-core 同物理同采集）接入 Cocos Creator 3.8.8 时，
> 连续挖出 7 层 bug。本文记录症状→根因→修复，供以后接入新引擎/新版本时对照排查。
> 核心教训写在最后。

---

## Bug 链（按发现顺序）

### 1. `director.game` 不存在 → onLoad 崩溃

- **症状**：headless 跑 Cocos 页面，无 HUD、无报错（错误被吞）
- **定位**：页面里手动 `addComponent(cc.js.getClassByName('CocosBench'))` 重放，拿到真实堆栈：`Cannot set properties of undefined (setting 'frameRate')`
- **根因**：Cocos 3.8 的 game 实例要从 `'cc'` 直接 import（`import { game } from 'cc'`），`director.game` 不存在
- **修复**：`(director.game as any).frameRate` → `game.frameRate`

### 2. 场景挂脚本不落盘

- **症状**：IDE 里"添加组件"看似成功，`bench.scene` 文件里搜不到 CocosBench，构建产物也没有
- **根因**：多轮 IDE 操作 + 外部 git checkout 场景文件，编辑器内存态和磁盘态打架，保存没真正写盘
- **修复**：**放弃场景挂载，改运行时自动挂**——模块顶层监听 `Director.EVENT_AFTER_SCENE_LAUNCH`，启动后 `canvas.addComponent(CocosBench)`。场景文件零依赖
- **教训**：Cocos 场景 JSON 是内部序列化格式，**手写必炸**（试过一次，反序列化直接报 `Cannot read properties of undefined`）。要么 IDE 挂+验证落盘，要么代码自挂

### 3. 引擎缺陷：WebGL 后端 `device.numDrawCalls` 恒 0

- **症状**：dc 采样 600 帧全 0，但页面正常渲染
- **定位**：读引擎源码 `cocos/gfx/webgl2/webgl2-command-buffer.ts:81`——`begin()` 里 `_numDrawCalls = 0` **清零后从不递增**（全不到 `_numDrawCalls++`）。WebGPU 后端有计数（`webgpu-command-buffer.ts:652`）
- **修复**：WebGL 臂不用引擎计数器，改 **WebGL API hook**（与 Egret probe 同口径）：
  hook `WebGLRenderingContext.prototype` 的 draw 函数，按 `draw增量/frame增量` 出窗口均值

### 4. 2D 合批走 `WEBGL_multi_draw` 扩展（hook 抓不到）

- **症状**：API hook 只抓到 240 次 draw（应为每帧多次）
- **定位**：编译产物搜 `WEBGL_multi_draw` 8 处——Cocos 2D batcher 优先用 multi_draw 扩展批量提交，**扩展方法挂在 getExtension 返回的对象上，不在原型上**
- **修复**：包装 `prototype.getExtension`，引擎请求 multi_draw 扩展时拦截返回对象、hook 其上所有 draw* 方法

### 5. probe 注入时机 + HTML 嵌套 script

- **症状**：probe 放编译产物尾部→来不及（引擎先建上下文先拿扩展）；改注入 index.html→页面直接挂
- **根因**：把完整 `<script>...</script>` 插进了**已有 script 块内部**，嵌套标签破坏 HTML 解析（`Unexpected token '<'`）
- **修复**：build.js 在 `System.import('./index.js')` 前注入**裸 JS 语句**（不带 script 标签）——早于一切引擎代码

### 6. 精灵 layer 不匹配 → 相机裁掉全部精灵

- **症状**：修完 3/4/5 后 dc 仍 0，截图 31KB（几乎全黑）
- **定位**：dump 场景树——Canvas layer=33554432（UI_2D），`new Node()` 默认 layer=1073741824（DEFAULT）。**Camera 只渲染 UI_2D 层**，5000 个精灵全部被裁
- **修复**：`n.layer = 1 << 25`（UI_2D）
- **教训**：Cocos 相机按 layer 裁剪，**程序创建的节点必须手动设 layer**。此 bug 最阴险：fps=60、采样正常、无报错——只有截图/draw 数能暴露"根本没画"

### 7. `clearAll` 删掉了场景 Camera → 黑屏

- **症状**：设了 layer 还是不渲染；场景树 dump 发现 **Camera 节点消失了**
- **根因**：`init() → clearAll() → root.removeAllChildren()`，root=Canvas，**Camera 是 Canvas 的子节点**，第一次 init 就被移除
- **修复**：适配器用**独立容器节点**（Canvas 下新建 `BenchRoot`），精灵全放里面，clearAll 只清容器
- **教训**：适配器的 root 不能用场景结构节点（Canvas/Scene），必须自建容器

## 修复后验证（闭环证据）

| 指标 | bug 期 | 修复后 |
|---|---|---|
| probe draw 计数（23s） | 240 | **3700** |
| 截图大小 | 31KB（近黑屏） | **1.5MB**（满屏兔子） |
| drawCall | 0 | **5** |
| 数据有效性 | 无效（纯 JS 无渲染） | 有效 |

**必做的渲染验证**：截图看内容 + probe 计数看量级。**fps=60 不代表在渲染**——
只测逻辑不测渲染的"假基准"是最危险的坑。

## 三引擎 drawCall 采集口径（现状）

| 引擎 | WebGL | WebGPU |
|---|---|---|
| Egret | API hook（drawElements/drawArrays 窗口均值） | 批处理器 `_lastBatchCount` |
| Laya | `Laya.LayaGL.statAgent.getElementData(StatElement.CT_2DDrawCall)`（注意在 L 命名空间下，globalThis.LayaGL 不存在） | 同左（webgpu_2D.js 有记录） |
| Cocos | API hook（原型 4 个 draw 变体 + multi_draw 扩展包装） | `device.numDrawCalls`（有计数） |

注意：各家"drawCall"语义有差异（Egret/Cocos=GPU 提交次数，Laya=合批后渲染元素数），数量级可比，汇报时标注。

## 本地工作流（人机分工）

```bash
# 起/重建站点（改代码后）
node bench/web/build.js        # 组装 bench/web/dist/
node bench/serve.js 8700       # 本地服务 → http://127.0.0.1:8700/
```

- **我（agent）**：改代码、起服务器、headless 采集（`node bench/run-bunny.js [count] [variant]`）
- **你（浏览器）**：人工验证页面/HUD/交互，跑真机 WebGPU（本机虚拟显示环境拿不到 WebGPU adapter，必须真机浏览器测）
- 快速体检脚本：`node bench/diag-probe.js`（probe 计数）、`node bench/diag-shot.js`（截图看渲染）

## 新引擎接入 checklist（防再踩）

1. 精灵节点 layer 与相机可见层一致？
2. 适配器 root 用自建容器，不碰场景结构节点（相机/灯光）？
3. drawCall 读数**实测验证过非 0**？（截图 + 计数双确认）
4. API 路径在**发布产物**里验证（不是 IDE 预览）——命名空间/裁剪可能不同
5. headless 出数后，截图确认"真的在渲染"
